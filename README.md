# typst-snapshots

This project is not affiliated with or endorsed by Typst GmbH.

Exact per-release snapshots of the Typst command-line interface: the `--help`
output of every subcommand and behavior-probe evidence, for every stable Typst
release from `0.1.0` onward.

This corpus is the compatibility evidence behind
[`@flukxr/typst-api`](https://github.com/flukxr/typst-api), a typed,
version-aware Node.js API over the native Typst CLI. It is not used at runtime
and ships in no package. It is public so that every compatibility claim the API
makes can be checked against the raw output it was derived from.

## What is in here

One directory per exact stable Typst release. Patch releases are separate
compatibility checkpoints and are never collapsed into their minor version.

```text
<version>/
  manifest.json              release, package revision, platform/arch, probe status
  <command>-help.json        structured capture of `typst <command> --help`
  <command>-help.stdout.txt  raw stdout of the same run
  <command>-help.stderr.txt  raw stderr of the same run
  behavior/<probe>.json      behavior-probe evidence (exit codes, outputs)
_diffs/<old>__<new>.md       help-output delta between consecutive releases
```

A command that does not exist in a release is still captured: its failed run
is the evidence that it is absent.

`_diffs/` is the place to start when you want to know what changed between two
Typst releases on the command line, for example
[`_diffs/0.14.2__0.15.0.md`](_diffs/0.14.2__0.15.0.md).

## Provenance

Every file is generated by running a real Typst binary for the exact release.
The binaries come from the
[`@flukxr/typst-cli`](https://github.com/flukxr/typst-cli) npm distribution,
pinned to the release, so a snapshot can be reproduced from its
`manifest.json` (`typstVersion` and `packageVersion`) alone.

Captured output is stored as the CLI printed it, with these exceptions:

- line endings are LF (`.gitattributes`); the `_diffs` comparison also ignores
  trailing whitespace, so it shows CLI changes rather than host formatting;
- absolute paths are replaced (`<workdir>`), and executable paths are kept
  relative to the collector cache;
- no hostnames, user names, environment values or installed fonts are
  recorded.

The corpus was collected on Windows x64, so help texts name the binary
`typst.exe`.

## Regenerating

Every file here is generated; do not edit it by hand. The collector, the
normaliser, the differ and the behavior probes live in
[`flukxr/typst-api`](https://github.com/flukxr/typst-api) under `scripts/`.
With both repositories cloned next to each other:

```sh
cd typst-api
npm ci && npm run build
export TYPST_API_SNAPSHOT_ROOT=../typst-snapshots
node scripts/collect-cli-snapshots.mjs           # help snapshots per release
node scripts/collect-cli-behavior-snapshots.mjs  # timing and invalid-eval captures
node scripts/normalize-cli-snapshots.mjs
node scripts/compare-cli-snapshots.mjs           # regenerates _diffs/
npm run probes:behavior                          # behavior/<probe>.json
npm run generate:flags                           # CLI flag inventory in typst-api
```

The collector skips releases that already have a `manifest.json`; pass
`--versions X.Y.Z` to select releases and `--force` to recollect them. A
forced collection removes the whole release directory, including
`behavior/`, so run the behavior probes again afterwards.

New Typst releases are prepared by a nightly job in `flukxr/typst-api`, which
opens a pull request here with the new snapshots. Changes are reviewed before
they are merged; nothing is merged automatically.
